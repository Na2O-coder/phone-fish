# 10 · GitHub 发布与维护

## 发布前检查

- [ ] SnowLuma 授权问题已确认（不包含二进制/rootfs/自动部署脚本）
- [ ] 仓库里没有 config.json/bridge.env/state.json/memory.db/conversation.db/logs/cookies
- [ ] 没有真实 QQ/群/API key/IP/token/密码
- [ ] 测试通过（18 项）
- [ ] redact_check 通过
- [ ] smoke_test 通过
- [ ] 视频/截图的演示号与线上号分离

## 建议仓库名

~~~text
phone-fish
~~~

先 private 建仓，自己 review 一遍，再转 public。

## 手动发布（有 token 时）

~~~bash
cd /sdcard/agent/work15/release/phone-fish
python3 tests/bridge_v2/run_all.py
python3 tools/redact_check.py .
python3 tools/build_release.py
~~~

然后：

1. 在 GitHub 创建私有仓库 phone-fish；
2. 把 staging 目录作为独立 git 仓库首次提交（不要从旧工作区根目录带历史）；
3. push；
4. 在 Releases 上传：
   - phone-fish-v0.3.zip
   - memes.db
   - memewiki-LICENSE.txt
   - SHA256SUMS-v0.3.txt
5. 确认没有 secrets 后再 public；
6. README/视频简介填仓库链接。

> 如果本地没有 git，可以用 GitHub API/网页上传，或提前安装 git；不要把 token 写进脚本/仓库。

## 版本维护

- 修改 bridge/文档后：更新 CHANGELOG.md、跑测试、重新 build；
- 变更配置 schema 时写迁移说明；
- 不要 force-push 已公开的 release tag；
- 收取 issue 时先让用户提供脱敏日志，不要让对方上传 config/state/db。
