# 12 · 设备兼容性检测

> 目标：在装虚拟机之前，用只读命令判断设备适合硬件虚拟化（Gunyah / GenieZone / KVM）还是软件模拟，并留下可对比的记录。

## 1. 先记录这些信息

在手机 Root Shell 或终端里执行（能取到多少算多少，不要猜）：

~~~bash
getprop ro.product.model
getprop ro.product.manufacturer
getprop ro.board.platform
getprop ro.build.version.release
uname -a
nproc
free -h
df -h /data /sdcard 2>/dev/null || df -h
ls -l /dev/gunyah /dev/gzvm /dev/kvm 2>&1
~~~

如果某个节点不存在，不要直接下结论说“设备不支持硬件虚拟化”——有些设备的节点名称或权限不同，以 DroidVM 的实际检测结果为准。设备节点存在也不等于 VM 一定能启动。

## 2. 检查 DroidVM 和后端

打开 DroidVM，确认：

- DroidVM 已获得 Root 权限；
- 能看到可用的虚拟化后端（Gunyah / GenieZone / KVM，具体取决于机型）；
- 能创建一个最小 Linux VM，并正常启动到 shell；
- VM 内能看到预期的 CPU 核数和内存。

如果 DroidVM 无法启动 VM，先记录错误，不要反复重建。

## 3. 在 VM 内做一次只读检查

~~~bash
uname -a
nproc
free -h
df -h /
cat /etc/os-release | head
systemd-detect-virt 2>/dev/null || true
ls -l /dev/gunyah /dev/gzvm /dev/kvm 2>&1 || true
~~~

> VM 内不一定能直接看到宿主机的虚拟化节点；宿主机检查以上面的 Root Shell 结果为准。

通过标准：

- 内核是 aarch64 / arm64；
- 可用内存和磁盘满足 SnowLuma + bridge 的最低要求；
- VM 能稳定运行，不会一启动就被手机后台杀掉。

## 6. 结论怎么写

- **有 Root + DroidVM 能启动 VM**：优先硬件虚拟化，进入 [02-手机与DroidVM准备](02-手机与DroidVM准备.md)。
- **没有 Root / 没有可用硬件虚拟化后端**：先阅读 [00-选择虚拟机运行路线](00-选择虚拟机运行路线.md)，把软件模拟标为实验性，再决定是否尝试。
- **VM 能启动但 SnowLuma 跑不动**：记录内存、CPU、磁盘和日志，不要用“手机太差”一句话带过。
