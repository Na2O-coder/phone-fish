# 08 · 运维、备份与排错

## 启动顺序

1. VM 启动完成；
2. SnowLuma 服务/进程启动；
3. 等 OneBot 3001 监听；
4. bridge 启动并连上 WS。

~~~bash
sudo systemctl restart snowluma
sudo systemctl restart snowluma-bridge
sudo systemctl status snowluma snowluma-bridge --no-pager
~~~

## 日志

~~~bash
journalctl -u snowluma-bridge -n 100 --no-pager
tail -f /opt/snowluma/bridge/bridge.log
curl -H "X-Auth-Token: 你的TOKEN" http://127.0.0.1:32146/health
~~~

## 备份

需要备份：

- /opt/snowluma/bridge/config.json
- /opt/snowluma/bridge/state.json
- /opt/snowluma/bridge/memory.db
- /opt/snowluma/bridge/conversation.db
- /opt/snowluma/bridge/prompts/（如果你改过）
- SnowLuma 自己的 data/config（按官方说明）

不要备份/外发：

- bridge.env（含密钥）
- cookies
- 日志中的私聊内容

示例：

~~~bash
sudo mkdir -p /opt/snowluma/backups/manual
sudo cp -a /opt/snowluma/bridge/config.json /opt/snowluma/bridge/state.json   /opt/snowluma/bridge/memory.db /opt/snowluma/bridge/conversation.db   /opt/snowluma/backups/manual/
sudo chmod -R 600 /opt/snowluma/backups
~~~

备份文件本身也含隐私；不要发群、不要上传公开网盘。

## 恢复

1. 停 bridge；
2. 用备份覆盖对应文件；
3. 检查 config.json 权限 600；
4. 启动 bridge；
5. 看日志和 /health。

## 常见问题

| 现象 | 排查 |
|---|---|
| QQ 不回复 | SnowLuma 是否在线；OneBot 是否收到事件；bridge 是否连上 WS；autoReply 是否开启；白名单/冷却/睡眠 |
| OneBot 401 | onebotToken 不一致；token 里有空格/换行 |
| 控制面 401 | X-Auth-Token 与 bridge.env 的 BRIDGE_CONTROL_TOKEN 不一致 |
| bridge 启动失败 | python3 版本、config.json 语法、端口 32146 被占用 |
| 端口被占用 | ss -ltnp 查 3001/5099/32146；停掉重复进程 |
| 手机杀 VM | 关闭电池优化、允许后台、锁后台；减少同时运行 App |
| 重启后缓存全 miss | 切换 thinking/改 prompt/重启后的首次冷启动；之后会恢复 |
| 扫码后掉线 | 不要官方 QQ 同时登录；网络稳定；少重建环境 |
| 内存不足 | VM 3 GB、清理后台；不要同时跑大模型/视频 |

## 安全事件处理

如果 key/token 泄露：

1. 立即停 bridge；
2. 吊销/轮换 DeepSeek key、OneBot/bridge token；
3. 修改 SSH/VNC 密码；
4. 检查日志/备份是否被外传；
5. 重新运行 bootstrap 或手动更新 config.json。
