# 01 · 架构与原理

## 目标

在一台安卓手机上，长期运行一个 QQ 小号，并让它像群友一样聊天、记忆、反思、主动说话。没有电脑、没有云服务器。

> 上层架构对 KVM 和软件模拟两条路线通用；两条路线的选择、检测和限制见 [00-选择虚拟机运行路线](00-选择虚拟机运行路线.md)。

## 架构（KVM 路线，推荐）

~~~text
Android 手机（root，DroidVM）
└── Ubuntu VM（真内核）
    ├── snowluma.service
    │   └── chroot /opt/snowluma-root
    │       ├── QQ 客户端 + SnowLuma
    │       ├── WebUI  :5099
    │       ├── OneBot HTTP :3000
    │       └── OneBot WS   :3001
    └── snowluma-bridge.service
        └── /opt/snowluma/bridge/snowluma_service.py
            ├── 连接 127.0.0.1:3001
            ├── 调用 DeepSeek API
            └── 处理 QQ 命令/记忆/关系/睡眠/缓存
~~~


## 软件模拟路线（Experimental）

没有 Root 或没有可用 KVM 时，可以把“Android → DroidVM → Ubuntu VM”替换成软件模拟虚拟机，上层 SnowLuma / OneBot / bridge 尽量保持一致。

这条路线目前是实验性：CPU 开销、发热和耗电可能明显增加，且尚未完成端到端实测。不要把它描述成与 KVM 性能相同的替代方案。

## 为什么不是 PRoot / udocker

早期路线尝试在 Operit 的 PRoot 里用 udocker 跑 SnowLuma，结论是：

- PRoot 没有真正的 namespaces/cgroups/overlayfs；
- Docker 守护进程无法运行；
- udocker 的 proot 套 proot 对 execve 不稳定；
- 即使容器启动，QQ/Chromium 等外部进程也容易失败。

所以最终改成 **DroidVM 真虚拟机**。真内核让 chroot 里的 QQ、Xvfb、Node 都能正常工作。

## 为什么不是 Docker

当前 DroidVM 的自定义内核缺少 overlay、iptables/nftables、fuse 等模块，Docker 守护进程起不来。于是把 SnowLuma 官方 Docker 镜像的 rootfs 取出，用 chroot 原生运行：

- 保留官方 rootfs 里的 supervisor/Xvfb/QQ/SnowLuma；
- 绑定 /proc、/sys、/dev、/dev/pts、/dev/shm；
- 绑定数据目录到 VM 的 /opt/snowluma/data；
- 用 systemd 管理，重启后自动恢复。

这条路线省掉了 vfs 的 13 GB 磁盘占用，但需要你自行从官方渠道取得 SnowLuma rootfs，并遵守其 EULA。

## 数据流

1. QQ 消息进入 SnowLuma；
2. SnowLuma 通过 OneBot v11 WS 把事件推到 bridge（127.0.0.1:3001）；
3. bridge 判断是否回、谁在说话、是否被 @/引用，构造上下文；
4. bridge 调用 DeepSeek（可带 web_search/记忆/表情等工具）；
5. 回复经 OneBot 发回 SnowLuma，再由 QQ 客户端发出；
6. bridge 把聊天 turn、记忆、关系、日报写入自己的 SQLite/JSON 状态。

## 缓存与上下文

- 系统 prompt 稳定；
- 每日聊天按“追加式 transcript”保存；
- 每轮把历史用户内容（含当轮动态 prompt/图片）原样重放，避免前缀变化；
- 跨天不重置，达到约 70% 上下文（默认 700k tokens）才做检查点压缩；
- 压缩时保留最近 80 个 turn，老内容归档；缓存前缀只冷启动一次；
- 这些是 bridge 的行为，不影响 SnowLuma 本身。

## 组件边界

| 组件 | 负责 | 是否在本仓库 |
|---|---|---|
| SnowLuma | QQ 协议、WebUI、OneBot | 否，官方软件 |
| DroidVM | 安卓上的真虚拟机 | 否，官方 APK |
| bridge | 回复策略、DeepSeek、记忆/关系/缓存 | 是，MIT |
| DeepSeek | 模型 API | 否，需要自己的 key |
| 梗百科 DB | 本地梗查询 | 可选 release asset，MIT |

## 设计原则

- 不写关键词黑名单，让模型判断语气和关系；
- 只硬编码机械/安全行为（频率、权限、端口、失败重试）；
- 不追求“每条都回”，允许潜水、沉默、短句；
- 所有凭据走本地配置，不进入 Git；
- 不公开个人聊天、关系、人设。
