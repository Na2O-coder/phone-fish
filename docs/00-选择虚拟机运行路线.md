# 00 · 选择虚拟机运行路线

> 先选路线，再装系统。选错路线会在 Root / KVM 上反复卡住。

phone-fish 的上层结构是共用的：

~~~text
Android 手机
└── 虚拟机（KVM 或软件模拟）
    └── Ubuntu
        └── SnowLuma + OneBot
            └── phone-fish bridge
                └── DeepSeek API
~~~

两条路线只在“虚拟机怎么运行”这一层不同，SnowLuma、OneBot 和 bridge 的配置尽量保持一致。

## 路线 A：KVM 硬件虚拟化（推荐）

适合：

- 已经 Root 的安卓手机；
- 处理器、内核和固件提供可用的硬件虚拟化能力；
- 希望长期运行，并尽量减少虚拟机的额外性能开销。

要求：

- Android 设备（系统版本以 DroidVM 官方要求为准）；
- Root 权限；
- DroidVM 能识别并使用可用的虚拟化后端（Gunyah / GenieZone / KVM，具体看机型）；
- 建议至少 8 GB RAM，预留约 25 GB 存储；
- 一台 QQ 小号和一个 DeepSeek API key。

优点：

- 使用处理器提供的硬件虚拟化能力；
- CPU 执行效率通常更接近原生环境；
- 相比纯软件模拟，额外的 CPU 开销通常更低；
- 更适合长期运行 Linux 服务。

注意：

- **处理器型号不等于支持 KVM。** 骁龙 8 Gen 3 / 8 Elite 或天玑旗舰只是“可以优先检查”，最终取决于厂商内核、固件和虚拟化接口是否开放；
- 即使 `/dev/kvm` 存在，也不保证 DroidVM 一定能启动虚拟机，必须实际启动测试；
- KVM 不是零开销。内存、设备模拟、I/O 和后台运行仍然会有成本。

## 路线 B：软件模拟虚拟机（Experimental / 实验性）

适合：

- 没有 Root 权限；
- 设备没有可用的 KVM；
- 愿意接受性能、发热和续航损失；
- 想在更多安卓设备上尝试运行 Linux。

原理：

通过软件模拟 CPU 和相关硬件环境运行 Linux，再在 Linux 中部署 SnowLuma 和 bridge。

优点：

- 不需要可用的 KVM 硬件虚拟化；
- 对设备底层虚拟化能力的依赖相对较低。

缺点：

- CPU 性能损耗可能明显增加；
- 相同负载下可能增加耗电和发热；
- 启动、编译和服务响应可能更慢；
- 长期运行体验通常不如 KVM。

**当前状态：实验性。** 本项目还没有完成软件模拟路线的端到端实测（系统启动、SnowLuma 登录、OneBot 通信、长期运行）。在完成实测前，不要把它写成“已完整支持”。

## 怎么选

1. **有 Root + 可用 KVM**：优先走路线 A。
2. **没有 Root 或没有 KVM**：先按 [12-设备兼容性检测](12-设备兼容性检测.md) 做只读检查，再决定是否尝试路线 B。
3. **路线 B 运行过慢或无法启动 SnowLuma**：换设备，或放弃在当前设备上部署。

## 两条路线的边界

- 上层 SnowLuma / OneBot / bridge 的配置可以共用；
- 虚拟机初始化步骤不能混用：KVM 专用命令不要套到软件模拟环境里；
- 软件模拟路线必须先标注“实验性”，通过实际部署、性能测试和长期运行后，再升级为正式支持；
- 任何一条路线都不承诺 QQ 账号安全，也不承诺 SnowLuma 不封号。
