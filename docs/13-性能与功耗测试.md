# 13 · 性能与功耗测试

> KVM 的“低开销”是相对软件模拟而言，不是零开销。当前没有统一实测数据，本文先给测试方法，不编造结论。

## 1. 要测什么

| 指标 | 说明 |
|---|---|
| VM 启动时间 | 从点击启动到 SSH / shell 可用 |
| SnowLuma 就绪时间 | 从 VM 启动到 WebUI / OneBot 可用 |
| 空闲内存 | VM 启动后、无消息时的内存占用 |
| 空闲 CPU | 无消息时的 CPU 占用 |
| 消息延迟 | 从 QQ 消息到 bridge 开始请求 / 回复发出，记录 p50 / p95 |
| 功耗 | 相同负载下的 mAh/h 或 W |
| 温度 | 连续运行 1 小时后的电池 / SoC 温度 |
| 稳定性 | 1 小时 / 24 小时是否掉线、OOM、被杀后台 |

## 2. 测试矩阵

至少对比：

- KVM 硬件虚拟化；
- 软件模拟虚拟机（如果设备支持）。

保持相同条件：

- 同一台手机、同一版 DroidVM；
- 相同 VM 配置（CPU / 内存 / 磁盘）；
- 相同 SnowLuma 版本和 OneBot 配置；
- 相同 QQ 消息负载；
- 屏幕亮度、网络、充电状态一致。

## 3. 采样方法

### 时间

在手机和 VM 里同时记录时间戳，或在 bridge 日志里记录消息到达 / 请求开始 / 回复发出。

### CPU / 内存

~~~bash
free -h
top -b -n 1 | head -20
vmstat 1 5
~~~

有 `pidstat` 时：

~~~bash
pidstat -p ALL 1 5
~~~

### 功耗

不同机型接口不同，优先用外接功率计；没有功率计时可尝试：

~~~bash
cat /sys/class/power_supply/battery/current_now
cat /sys/class/power_supply/battery/voltage_now
cat /sys/class/power_supply/battery/temp
~~~

注意单位因机型而异，不要直接把读数当成功耗结论。

### 温度

~~~bash
cat /sys/class/thermal/thermal_zone*/type
cat /sys/class/thermal/thermal_zone*/temp
~~~

## 5. 结论怎么写

- 只写实际测到的数据；
- 没有数据就写“未测”，不要写“几乎不耗电”“性能一样”；
- 区分“理论预期”和“本机实测”；
- 软件模拟路线的数据要单独标注实验性。

## 6. 最低验收

在把某条路线写成“推荐”之前，至少完成：

- VM 能连续运行 24 小时；
- SnowLuma 登录不掉线；
- OneBot 能收发消息；
- bridge 能正常回复；
- 没有明显 OOM / 被系统杀后台；
- 记录一次真实功耗和温度。
